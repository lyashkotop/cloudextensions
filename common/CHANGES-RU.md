# StreamBundle v64: исправления выбора данных

Это исправление разбора метаданных, а не подтверждение работоспособности всех сайтов.
Размер пакета — 300 669 байт. Сохранены все 27 регистраций провайдеров.

## Что исправлено

- Название выбирается из полного значения источника. Уже выбранное полное название
  карточки сохраняется при открытии, в том числе если страница отдаёт другой язык.
  Заголовок вкладки с брендом сайта больше не подменяет полноценное имя из VideoObject/h1.
  Обрезание одной строки в интерфейсе приложения отдельно плагином не управляется.
- Видимые метки конкретного видео имеют приоритет перед video:tag в head. На Semyana
  добавлены video-taxonomy/tax-tags/tax-feature-tags внутри VideoObject. Лимит увеличен
  до 128 меток. Исходное написание меток сохраняется, слова из описания в теги не превращаются.
- Если известная страница не дала собственных тегов, чужой список из общего обработчика
  не подставляется. Для объявленного пустого блока тегов не используется запасной SEO-список.
- Пустое индивидуальное поле описания больше не заменяется общим SEO-текстом страницы.
  Если описания нет, выдуманное описание или фраза-заглушка не добавляется.
- Первой строкой выводится точная длительность из опубликованного значения источника:
  microdata, VideoObject JSON, video:duration или данных Beeg API. Поддерживаются ISO 8601,
  секунды, HH:MM:SS, MM:SS и дробные секунды. Округлённые минуты Duration не используются.
  Если точного времени нет, строка длительности отсутствует. Обещать точное время при
  отсутствии данных источника нельзя.
- Кэш категорий, из которого читает фильтр, согласован с выбранными метками видео.
- В существующем запросе похожих Semyana исправлен селектор: #related-videos[hx-get]
  вместо отсутствующего атрибута data-no-deferred-request. Междоменные запросы не добавлялись.

## Что проверено на реальных данных

Получены HTML главной страницы Semyana, одной карточки и её блока related. Содержимое
фото и видео не отображалось. Поиск роликов по текстовым запросам в этом прогоне не выполнялся.

Код из готового DEX преобразован в JVM-байткод и исполнен на этих HTML. Исполнялись
настоящие BundleMetadata, DetailMetadata, WebVideoParser и relatedResults. Для загрузки
классов использовались объявления типов Android API; сетевые ответы ими не имитировались.
Это тест обработки данных, а не запуск приложения Android.

До исправления обработчик выдавал 40 тегов; только 2 совпадали с видимыми метками ролика.
После исправления — 52 метки, все совпали с источником. Название точно совпало с h1
и значением карточки в выдаче. Тест альтернативного языкового заголовка сохранил выбранное
название. Длительность совпала с опубликованным значением, а фиктивные 999 минут тестового
объекта не использовались. SEO-описание исключено. Реальный запрос related ответил HTTP 200:
парсер обработал 10 карточек, после штатного фильтра списка осталось 10.

Дополнительно прошли 44 проверки на нейтральных данных, проверка настоящей ошибки
сборщика, целостность ZIP/DEX и сохранение публичных методов. Инструкции 587 классов
совпадают с v63. Тестовые классы в пакет не включены. Подробности — VALIDATION.json.

## Что остаётся неподтверждённым или неисправленным

- Работа кнопки в интерфейсе Cloudstream и всех 27 провайдеров целиком не проверена.
- Конкретная карточка пользователя не воспроизведена: адрес не предоставлен.
- Пустая выдача YouJizz не воспроизведена и не исправлена.
- HTTP 403 PunishBang/MissAV и no links found не исправлены. Потоки и зеркала не восстанавливались.
- Нельзя получить отсутствующие сведения источника или гарантировать доступность внешнего сайта.

Нейтральные примеры в tests/ соответствуют структуре обнаруженной разметки, но не выдаются
за реальные страницы. Реальный HTML с названиями/метками не включён в исходный архив;
в опубликованном результате оставлены только счётчики и признаки совпадения.
