# Исправления превью и зависаний RU/EN

Проверка 2026-11-16. Изменены русские и английские источники (37 модулей).
Отдельные японские реализации не перерабатывались.

Подтверждённые причины и исправления:

- На реальной карточке CosXPlay значок страны находился перед кадром. Общий парсер брал первый img и возвращал флаг. Теперь выбирает изображение видео, пропуская значки, флаги, логотипы и заглушки, продолжает поиск среди остальных изображений.
- Все RU/EN источники сохраняют настоящее превью из выдачи при открытии карточки. Невалидная/пустая обложка не стирает его. Учитываются перенаправления; свежая страница заменяет устаревший адрес через три минуты.
- Передаются Referer/User-Agent и подходящие домену изображения cookies HTTP-клиента. Проверка каждой фотографии дополнительным запросом перед показом не добавлена.
- Поиск/главная/карточка ограничены 22 секундами, сетевой запрос с ожиданием очереди — 18, Cloudflare-обработчик — 7. Ограничения завершают ожидание ошибкой; они не превращают заблокированный сервер в работающий.
- Запросы рекомендаций и дополнительных полей имеют отдельный короткий срок ожидания. Сбой необязательного запроса не должен удерживать основную карточку.
- Английские обработчики load используют общий кэш страницы; обогащение полей не повторяет тот же GET. У Epawg убран строковый адрес `null` при отсутствии preview_url.
- Beeg получает обложку, категории, длительность и рекомендации из настоящего metadata API. Отсутствующее в API индивидуальное описание не генерируется.
- BDSMX: categories содержит настоящие метки даже при пустом tags. Добавлен разбор categories и categories_data, относительных адресов изображений.
- Добавлены актуальные области тегов EPorner, ForcedCinema, YouJizz, Whoreshub, CosXPlay. В описании удаляются рекламные предложения с сохранением настоящего текста.
- JSON-LD сопоставляется также с canonical/og:url и объектным mainEntityOfPage; thumbnailUrl может быть объектом.

## Живые проверки

37 источников: 35 главных/каталогов ответили 200, PunishBang и SpankBang — 403.
У BDSMX каталог JSON вместо HTML. У XNXX, XRares, TubeSafari, TubeBDSM проверен
настоящий раздел с видео, а не пустая/категорийная главная.

Взяты реальные страницы каталогов и по две карточки доступных HTML-каталогов;
производственный Kotlin-парсер отчитался длинами/счётчиками полей в metadata.json.
У API BDSMX/Beeg отдельно проверены поиск, две карточки и превью. Новый парсер BDSMX
также вызван на настоящем API JSON: 12 меток из 12 опубликованных категорий.

У 102 превью, выбранных Kotlin-парсером, проверены HTTP и первые 512 байт:
96 успешных изображений, 0 путей флагов. Остальные 6 — CDN `cdn2.pvvstream.pro`
(Noodle Magazine, UKDevilz): сетевой прокси среды отклоняет CONNECT кодом 403.
Это не HTTP-ответ самого изображения; доступность этих файлов на Android не подтверждена.
Четыре дополнительных превью API BDSMX/Beeg тоже прошли проверку.

Медиа не отображались и не воспроизводились. Проверка полей по настоящему HTML/JSON
и контроль пакетов не заменяют Android UI/Coil/WebView-проверку. Индивидуальное описание
на некоторых страницах отсутствует у источника: пустое поле не заполняется заголовком,
рекламой или выдуманным текстом. Все внешние 403/удалённые ролики не устранены.

69 регрессионных проверок: в том числе реальная структура флага перед превью,
сохранение фотографии при открытии и перенаправлении, неверный URL null, сохранение
описания без рекламного хвоста, ограничение обязательного/необязательного запроса.


## Полный путь SDK

С действительными сетевыми запросами вызваны search("guy",1) и load первой карточки
для всех 37 провайдеров, с теми же адаптерами, которые регистрирует расширение.
JVM-проверке предоставлены HTTP-прокси среды и библиотеки хоста (OkHttp 5 и serialization);
тестовые библиотеки не включаются в .cs3. Ответы HTTP не подменялись.

31 карточка открылась и сохранила адрес превью из выдачи; в пяти случаях выбранное
видео было скрыто действующим фильтром, PunishBang вернул 403. Максимум поиска
в этой серии — 2,44 с, открытия успешной карточки — 1,90 с. Отдельный запрос поиска
SpankBang в SDK прошёл, хотя прямой запрос его главной ранее давал 403.
Результаты без названий/изображений: runtime-sdk.json.

102 изображения проверены также обычным GET с User-Agent приложения, без Range:
по заголовкам файлов 96 имеют нормальные размеры (не маленькие иконки/заглушки),
шесть недоступны из-за CONNECT 403 прокси Noodle/UKDevilz. Пиксели не декодировались
и не отображались. Первоначальная попытка проверки размеров без User-Agent дала
три ложных 404 ProstoPorno; правильный заголовок приложения устранил их.

Закрывается тело ответа после неуспешной Cloudflare-попытки. Несовместимая библиотека
хоста (LinkageError) преобразуется в понятную ошибку с предложением обновить CloudStream,
вместо падения корутины загрузки. Абсолютный URL изображения обрабатывается даже при
старом сериализованном адресе закладки. Эти случаи добавлены в регрессионные проверки.

Это выполнение кода провайдеров через SDK на JVM, а не запуск Android UI/Coil/WebView.
По-прежнему не заявляется работоспособность каждого файла медиатеки или устранение
внешних блокировок. Индивидуальное описание не может появиться, если источник его не публикует.

## Проверка исключения фильтра

Пять источников, где первый результат guy скрывался фильтром (XVideos, hcBDSM,
BDSM Streak, ForcedCinema, EPorner), дополнительно вызваны с запросом lesbian.
Все пять вернули карточки, настоящие метки и описание; адрес превью сохранился,
название совпало с поиском. Открытие заняло 0,27–1,19 с. Таким образом, в этой серии
путь SDK search → load успешно проверен у 36 из 37 источников; PunishBang остался 403.
Доступность самих CDN-файлов Noodle/UKDevilz по-прежнему ограничена прокси среды.

Окончательная версия v81: 69 проверок ядра; Actions собрал все 49 пакетов,
после публикации проверены скачивание, SHA-256, манифест и единственная регистрация каждого.
