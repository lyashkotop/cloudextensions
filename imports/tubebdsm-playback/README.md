# TubeBDSM: внешние источники, метаданные и рекомендации

TubeBDSM отдаёт /out/ ссылки с HTTP-переходом на сайт источника. Теперь потоки запрашиваются с Referer конечной страницы, а при отсутствии прямых ссылок поддерживаемый экстрактор вызывается также для самой внешней страницы, а не только iframe.

Добавлены форматы: Next.js props.pageProps.firstVideo.sources/source (Tik.Porn), явные data-sources с разрешениями (Pornvio), const/let/var sources с file/src (Porner.TV). Next-видео принимается только при совпадении basePath с текущей страницей: соседние записи JSON-ленты не выдаются за выбранный ролик. Типы HLS/DASH задаются явно, без зависимости определения MIME от дополнительных библиотек хоста.

Для сайтов с уже установленным подходящим провайдером TubeBDSM может использовать его load/loadLinks и видеоинтерцептор. Это помогает источникам со своими API (проверен BDSMX). При отсутствии такого провайдера используется общий обработчик. Сам TubeBDSM не требует установки всех внешних провайдеров для обычных прямых форматов; делегирование — дополнительный путь.

Описание берётся из настоящего описания текущего видео. У Pornvio оно есть в VideoObject. У двух проверенных Tik.Porn/Porner.TV отдельное описание не опубликовано — оставлено пустым, без рекламного SEO и придуманного текста. Добавлены настоящие теги Next-видео и локальных категорий Porner, длительность из полей источника. Рекомендации берутся из initialRelatedVideos.data (Tik) и реальных блоков RelatedVideos/article.card (Porner/Pornvio); при отсутствии используется прежний поиск по опубликованному тегу.

Заголовки обложек внешнего источника больше не заменяются общим Referer агрегатора. Обложка, сохранённая из списка TubeBDSM, сохраняет Referer списка. Рекомендации содержат реальные адреса и изображения. Кнопку/раздел похожих видео отображает CloudStream по заполненному recommendations; интерфейс Android не запускался.

HLS: устранён повторный разбор SDK M3u8Helper, который мог неверно считать вертикальный 1080x1920 потоком 1920p. Для разрешения используется короткая сторона кадра: 1080x1920 → 1080p, 720x1280 → 720p. При нескольких кодеках на одно разрешение предпочтён AVC, затем HEVC, затем AV1; остаётся одна реальная ссылка на разрешение. Лимит объявленного качества 1080p сохранён; неограниченный мастер с более высокими дорожками не возвращается как Auto.

## Настоящие проверки

Через SDK load/loadLinks без просмотра содержимого:

- Tik.Porn: MP4 HTTP 206/ftyp, HLS с Auto/1080/720/540/360/270, 4 тега, 10 рекомендаций.
- Porner.TV: HLS HTTP 206/#EXTM3U, Auto/240/480/720, 3 тега, 8 рекомендаций.
- Pornvio: MP4 720p HTTP 206/ftyp, 5 тегов, настоящее описание, 42 рекомендации.
- BDSMX: через зарегистрированный провайдер SDK — MP4 HTTP 206/ftyp. В этом отдельном тесте проверялось извлечение файла, а не открытие карточки/фильтры.

live.json использует числовые quality SDK: 400 означает Unknown/«Оригинал», это не заявленное разрешение 400p. Скриншоты и воспроизведение видео не выполнялись. 117 проверок общего кода прошли, TubeBDSM скомпилирован и DEX/регистрация проверены.

## Ограничения

Проверены HTTP-переходы 55 источников из New/Popular/Top rated: 50 дали HTTP 2xx, это не доказательство воспроизведения всех 50. XGroovy, Yesvids, MyLust, TheyAreHuge ответили 403; AbXXX — 429. В Android challenge-обработчик может дать другой результат, но это не подтверждено. Удалённые, закрытые аккаунтом, платные или недоступные файлы не восстановлены. Воспроизведение всех роликов всех сайтов не заявляется; исправлены и подтверждены перечисленные реальные схемы. Полный отчёт HTTP: source-http-audit.json.
